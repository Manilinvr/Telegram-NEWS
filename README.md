# Система мониторинга новостей Новороссийска

Приватный веб-сервис для личного мониторинга городских новостей. Система
собирает публикации из открытых Telegram-каналов и сообществ VK, объединяет
сообщения об одном происшествии в единое событие, извлекает факты, готовит
редакционный черновик для Telegram и передаёт его владельцу на обязательную
ручную проверку.

**Автопубликация выключена.** Материал попадает в канал только после явного
подтверждения человека.

---

## Что система делает

```
Источник → Сбор → Сырая публикация → Нормализация → Медиа → Транскрипция
   → Извлечение фактов → Классификация → Дедупликация → СОБЫТИЕ
   → AI-черновик → Проверка лексики → Модерация → Финальная проверка → Telegram
```

- **Собирает** публикации из публичных Telegram-каналов и сообществ VK.
- **Объединяет** сообщения об одном происшествии: три канала, написавших об
  одном ДТП, дают одно событие с тремя источниками.
- **Различает** похожие, но разные происшествия: два ДТП в один день
  описываются почти одинаковыми словами, и совпадение лексики объединением
  не считается.
- **Извлекает факты** и отделяет их от предположений, сохраняя, из какой
  публикации взято каждое утверждение.
- **Расшифровывает видео** и помечает неразборчивые фрагменты, не додумывая
  неуслышанное.
- **Готовит черновик** для Telegram и **гарантированно не пропускает мат** —
  на нескольких независимых рубежах.
- **Показывает происхождение** каждого факта и ссылки на оригиналы.

## Требования

| Компонент | Версия | Обязателен |
|---|---|---|
| Node.js | 20.10+ (рекомендуется 22) | да |
| PostgreSQL | 14+ (рекомендуется 16) | да |
| pgvector | любая | нет — ускоряет поиск похожих публикаций |
| ffmpeg | любая | нет — нужен для длительности видео и транскрипции |
| S3 / MinIO | — | нет — по умолчанию медиа хранятся на диске |

Система намеренно работает и без необязательных компонентов: их отсутствие
отключает отдельные возможности, но не ломает конвейер.

## Быстрый старт

```bash
# 1. Зависимости
npm install

# 2. Конфигурация
cp .env.example .env
# Сгенерируйте секреты и впишите их в .env:
node -e "console.log('SESSION_SECRET=' + require('crypto').randomBytes(48).toString('base64url'))"
node -e "console.log('CSRF_SECRET=' + require('crypto').randomBytes(48).toString('base64url'))"

# 3. База данных (вариант с Docker)
docker compose up -d postgres
# Для Supabase см. docs/DEPLOY-SUPABASE.md — там отдельный каталог миграций.

# 4. Схема и справочники
npm run migrate
npm run seed

# 5. Учётная запись владельца — пароль будет показан ОДИН раз
npm run bootstrap:admin

# 6. Запуск: API, воркер и веб-панель
npm run dev
```

Панель откроется на <http://localhost:5173>, API — на порту 4000.

### Демонстрационные данные

Чтобы увидеть систему в работе до подключения реальных источников:

```bash
npm run seed:demo -w @nnm/backend
```

Скрипт создаёт вымышленную городскую повестку и прогоняет её через
**настоящий** конвейер — включая объединение публикаций в события и
генерацию черновиков. В production запускать не нужно.

## Фильтр нецензурной лексики

Требование «мат не должен попасть в публикацию» выполняется несколькими
независимыми рубежами, а не одной проверкой:

1. Исходный текст очищается перед передачей в модель.
2. Системный промпт прямо запрещает брань.
3. Готовый черновик проверяется по всем полям: заголовок, текст, подписи,
   цитаты, ключевые фразы из видео, Telegram-preview.
4. Текст проверяется заново при одобрении модератором.
5. Финальная проверка выполняется непосредственно перед отправкой.

Фильтр рассчитан на обход, а не на точное совпадение слов: распознаются
регистр, латиница, цифры вместо букв, повторы, пробелы и точки внутри слова,
невидимые символы, диакритика. Мат заменяется не звёздочками — предложение
удаляется или переформулируется, потому что маскировка оставляет смысл
читаемым.

**Проверку мата нельзя отключить.** Такой настройки нет ни в интерфейсе, ни
в API, ни в модели данных. Настраивается только политика по грубой брани и
дополнительные списки слов.

Проверить работу фильтра на конкретном тексте: **Настройки → Фильтр лексики**.

## Структура проекта

```
packages/
  shared/     — типы и контракты, общие для backend и frontend
  backend/    — API, воркеры, конвейер обработки
    src/modules/
      ingestion/    — адаптеры Telegram и VK
      media/        — скачивание вложений, ffmpeg
      transcription/— расшифровка видео
      ai/           — обращение к модели, эвристика, промпты
      dedup/        — эмбеддинги и объединение в события
      pipeline/     — построение событий и черновиков
      profanity/    — ProfanityGuard
      moderation/   — очередь ручной проверки
      publishing/   — отправка в Telegram
  frontend/   — панель мониторинга
docs/         — документация
scripts/      — резервное копирование
```

## Приватность

- Регистрация новых пользователей отключена.
- Панель и API доступны только после входа.
- Хранилище медиа не публично: файлы отдаются по коротко живущим
  подписанным ссылкам.
- Карта рисуется локально — содержимое ленты не уходит к картографическим
  сервисам.
- При `AI_PROVIDER=mock` и `EMBEDDING_PROVIDER=local` тексты новостей вообще
  не покидают контур системы.
