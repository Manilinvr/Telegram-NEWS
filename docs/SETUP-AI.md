# Настройка AI

## Провайдеры

| `AI_PROVIDER` | Что происходит | Когда использовать |
|---|---|---|
| `mock` | Разбор по правилам, без обращения к модели | Разработка, приёмка, работа без ключа |
| `anthropic` | Обращение к Claude | Рабочий режим |
| `openai-compatible` | Любая служба с интерфейсом OpenAI: DeepSeek, Groq, OpenRouter, локальная модель | Рабочий режим без счетов Anthropic |

### Режим `mock` — это не заглушка

При `AI_PROVIDER=mock` система остаётся **полностью работоспособной**:
публикации собираются, объединяются в события, получают черновик и
проходят модерацию. Разбор выполняется набором правил: классификация по
ключевым словам, факты — предложениями исходного текста, пометки
предположений по словам-маркерам («предположительно», «по предварительным
данным»).

Уверенность таких материалов намеренно занижена (0.4), чтобы они
гарантированно попадали к человеку.

Тот же механизм работает как **запасной вариант**: если модель недоступна
или вернула некорректный ответ, материал не теряется, а получает базовый
разбор и уходит на ручную проверку.

### Режим `anthropic`

```
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
AI_MODEL=claude-opus-5
AI_MAX_OUTPUT_TOKENS=4096
AI_TEMPERATURE=0.2
AI_TIMEOUT_MS=60000
```

Ключ получается в консоли Anthropic. Низкая температура выбрана
намеренно: задача — извлечь факты, а не сочинить текст.

### Режим `openai-compatible` — DeepSeek и другие службы

Протокол OpenAI поддерживают десятки служб, поэтому адрес и название
модели задаются переменными, а код не меняется. Для DeepSeek:

```
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://api.deepseek.com/v1
AI_API_KEY=sk-...
AI_MODEL=deepseek-chat
```

Ключ получается в консоли DeepSeek (platform.deepseek.com → API keys) и
требует пополненного баланса: без него служба отвечает
`Insufficient Balance`, и система продолжает разбор по правилам.

Важны все четыре строки. Чаще всего подключение не срабатывает так:

| Что видно | Причина |
|---|---|
| Провайдер `mock` в настройках | `AI_PROVIDER` не переключён — остальные переменные не читаются |
| `AI_BASE_URL` без `/v1` | Запрос уходит не на тот адрес, служба отвечает 404 |
| `AI_MODEL=claude-opus-5` | Название от Anthropic; DeepSeek такой модели не знает. Запуск останавливается с объяснением |
| Переменные заданы, разбор всё равно по правилам | Неверный ключ или исчерпан баланс — видно в проверке связи |

Другие службы подключаются так же, меняются только две строки:

```
# Groq
AI_BASE_URL=https://api.groq.com/openai/v1
AI_MODEL=llama-3.3-70b-versatile

# Локальная модель (Ollama), ключ не нужен
AI_BASE_URL=http://localhost:11434/v1
AI_MODEL=qwen2.5:14b
```

### Как убедиться, что модель действительно подключена

Настройки задаются переменными окружения на хостинге, где опечатку не
видно: при любой ошибке система **не останавливается**, а продолжает
разбор по правилам — внешне это выглядит как исправная работа.

Поэтому в разделе «Настройки → Общие» есть кнопка **«Проверить модель»**.
Она отправляет один короткий запрос и показывает ответ службы как есть:
неверный ключ, исчерпанный лимит и незнакомое название модели видны
дословно. Рядом, у строки «Провайдер AI», состояние показано постоянно:
`настроен` — модель используется, `не настроен: …` — названа причина.

То же состояние отдаёт `GET /api/diagnostics` в поле `ai.reason`, а
проверку связи выполняет `POST /api/diagnostics/ai-check`.

**Тексты новостей при этом уходят внешнему сервису.** Если это
неприемлемо, оставьте `mock` или подключите локальную модель через
совместимый интерфейс.

## Редакционный стиль

Тон подачи задаётся в интерфейсе: **Настройки → Стиль**. Правка промпта в
коде для этого не нужна — настройка хранится в базе и применяется к
следующему черновику.

| Настройка | Что делает |
|---|---|
| Тон | `Нейтральный` — информационная лента; `Официальный` — полные названия служб и строгие формулировки; `Живой` — простые слова и короткие фразы; `Телеграфный` — только суть |
| Длина краткого изложения | 1–6 предложений в поле `summary`, из которого собирается тело поста |
| Подпись в конце поста | Например `@novotoday`. Пусто — без подписи |
| Значки в посте | 📍 место, 🕒 время, 🎥 очевидцы. Выключены — те же сведения словами: «Место: …», «Время: …» |
| Дополнительные указания | Свободный текст до 2000 символов: как называть районы, каких слов избегать, что предпочитать |

Указания работают тем лучше, чем они конкретнее. «Район называть Мысхако,
а не посёлок» модель выполняет, «пиши интереснее» — почти нет.

### Граница настройки

Стиль управляет ТОНОМ и оформлением и не может отменить ни одного правила
работы с фактами. Свободные указания уходят в промпт отдельным разделом
**после** запретов, вместе с оговоркой, что при противоречии выполняются
правила. Даже если в поле написать «разрешаю додумывать детали», запрет
выдумывать факты останется в промпте, а результат всё равно пройдёт
проверку лексики на стороне системы — она моделью не управляется.

Перечень источников в конце поста настройкой не отключается: система не
выдаёт переработанный чужой материал за свой.

### Когда изменения вступают в силу

Стиль читается при подготовке КАЖДОГО черновика, поэтому перезапуск не
нужен. Уже созданные черновики остаются как были — их пересобирает кнопка
«Пересоздать черновик» в карточке события.

## Когда модель недоступна

Отказ модели не останавливает систему: новость разбирается набором правил
и доходит до модератора. Но качество при этом другое — текст не
переписывается, а собирается из предложений источника.

Чтобы это не оставалось незамеченным:

- отказ службы объясняется словами — исчерпанный лимит, нулевой баланс,
  неверный ключ и незнакомая модель называются прямо, с временем
  обновления лимита, где служба его сообщает;
- в журнал ошибок попадает одна запись «Модель недоступна» на час, а не
  по записи на каждую публикацию, и индикатор в боковой панели становится
  жёлтым;
- материалы, разобранные правилами, помечаются `RULES` (не `HUMAN`, как
  раньше) и при обслуживании возвращаются модели, когда она снова
  отвечает. Отбирается только то, что ещё ждёт модератора: опубликованное,
  отклонённое, взятое в работу и правленное человеком не трогается.

Проверки связи по расписанию нет намеренно: обслуживание идёт каждые 15
минут, и одни только проверки съедали бы 96 запросов в сутки — больше,
чем даёт бесплатный тариф целиком. Вместо этого используется отсрочка:
после записи о недоступности следующая попытка откладывается на полчаса.

## Что модель обязана и чего не должна делать

Правила заданы в системном промпте (`src/modules/ai/prompts.ts`) и
продублированы контролем на стороне системы:

Обязана: опираться только на переданные публикации, отделять факты от
предположений, помечать неподтверждённое, сохранять атрибуцию («по словам
очевидца»), писать собственный текст.

Запрещено: выдумывать факты и детали, выдавать предположение за факт,
использовать мат и оскорбления, копировать публикацию целиком, скрывать
происхождение сведений.

Ответ модели обязан быть структурированным JSON. Схема проверяется на
стороне системы: некорректный ответ отклоняется и не создаёт «мусорное»
событие.

## Эмбеддинги

Нужны для поиска похожих публикаций при объединении в события.

| `EMBEDDING_PROVIDER` | Описание |
|---|---|
| `local` (по умолчанию) | Детерминированные векторы, считаются на месте, без сети |
| `voyage` | Внешний сервис Voyage AI |

Локальный провайдер — не нейросетевые эмбеддинги. Он хорошо решает
задачу, которая стоит на практике: распознать, что два канала пишут об
одном происшествии, пересказывая одни и те же факты и имена. Признаки —
основы слов, биграммы и символьные триграммы — устойчивы к
переформулировкам и опечаткам.

Важно понимать его границу: если две публикации об одном событии написаны
**полностью разной лексикой**, локальный провайдер их не сблизит. Такие
случаи разводит не он, а совпадение конкретного места, времени и
категории — см. [ARCHITECTURE.md](ARCHITECTURE.md).

Внешний провайдер включается явно:

```
EMBEDDING_PROVIDER=voyage
VOYAGE_API_KEY=pa-...
VOYAGE_MODEL=voyage-3
EMBEDDING_DIMENSIONS=1024
```

При смене провайдера или размерности ранее сохранённые векторы
пересчитываются при следующей обработке публикации.

## Пороги объединения

```
DEDUP_TIME_WINDOW_HOURS=36   # окно поиска кандидатов
DEDUP_MERGE_THRESHOLD=0.78   # выше — объединять автоматически
DEDUP_REVIEW_THRESHOLD=0.62  # выше — отправить на проверку человеку
```

Значения подобраны по измерениям на реальных формулировках. Понижение
порога объединения увеличивает риск склеить два разных происшествия в одну
новость — ошибку, которую замечают далеко не всегда. Повышение приводит к
лишним отдельным событиям, что исправляется модератором одним действием.
