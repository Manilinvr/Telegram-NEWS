# Установка: от нуля до рабочего сайта

Инструкция для развёртывания «с нуля» без локальной машины: база — в
Supabase, приложение — на Render. Всё делается в браузере, кроме шага 5,
который выполняется один раз.

Порядок важен: база → секреты → приложение → владелец → источники.

---

## Что получится

Один веб-сервис, который отдаёт и панель, и API, и выполняет фоновые
задачи. Отдельный процесс воркера на старте не нужен.

Автопубликация выключена: система готовит черновик, публикация — только
после ручного подтверждения. Это требование проекта, а не настройка по
умолчанию.

## Шаг 1. База данных в Supabase

1. [supabase.com](https://supabase.com) → **New project**.
2. Задайте пароль базы и **сохраните его** — он понадобится в шаге 3 и
   больше нигде не показывается.
3. Дождитесь, пока проект перейдёт в состояние *Active* (1–2 минуты).

## Шаг 2. Схема — одним файлом

1. В проекте Supabase: **SQL Editor → New query**.
2. Откройте в репозитории файл **`supabase/setup.sql`**, скопируйте его
   **целиком** и вставьте в редактор.
3. **Run**. Если спросит про Row Level Security — **Run without RLS**:
   защиту включает сам файл, в конце, и правильным образом.

Успех выглядит как `Success. No rows returned`.

Проверьте результат — вставьте в новый запрос:

```sql
select
  (select count(*) from pg_tables where schemaname = 'public') as таблиц,
  (select count(*) from pg_tables where schemaname = 'public' and rowsecurity) as с_защитой,
  (select count(*) from pg_policies where schemaname = 'public') as политик,
  (select count(*) from schema_migrations) as миграций;
```

Ожидается `21 | 21 | 0 | 8`.

Ноль политик — это не упущение. При включённом RLS отсутствие политик
означает «запрещено всем, кроме владельца таблицы». Именно это закрывает
вашу базу от публичного REST API, который Supabase поднимает над схемой
`public` автоматически.

Если файл выдаёт `Схема уже установлена: таблица events существует` —
значит, установка прошла раньше. Повторять не нужно.

## Шаг 3. Строка подключения

**Project Settings → Database → Connection string → URI.**

Возьмите **Session pooler** (порт `5432`) или прямое подключение.
**Transaction pooler** (порт `6543`) не подходит: очередь задач держит
транзакции, а пулер отклоняет таймауты, которые приложение задаёт при
подключении.

Подставьте в строку пароль из шага 1 вместо `[YOUR-PASSWORD]`. Результат
выглядит так:

```
postgresql://postgres.abcdefgh:ПАРОЛЬ@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
```

## Шаг 4. Два секрета

Сгенерируйте **два разных** значения:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

Первое станет `SESSION_SECRET`, второе — `CSRF_SECRET`. Одно и то же
значение в обоих полях использовать нельзя.

Секреты не хранятся в репозитории — только в переменных окружения
хостинга.

## Шаг 5. Приложение на Render

1. [render.com](https://render.com) → **New → Web Service** → подключите
   этот репозиторий.
2. В репозитории есть `render.yaml`, поэтому команды сборки и запуска
   Render заполнит сам. Если он их всё же спросит:
   - **Build Command:** `npm ci && npm run build`
   - **Start Command:** `npm run start -w @nnm/backend`
   - **Health Check Path:** `/api/health`
3. Задайте переменные окружения:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | строка из шага 3 |
| `DATABASE_SSL` | `true` |
| `SESSION_SECRET` | первое значение из шага 4 |
| `CSRF_SECRET` | второе значение из шага 4 |
| `NODE_ENV` | `production` |
| `COOKIE_SECURE` | `true` |
| `TRUST_PROXY` | `true` |
| `RUN_WORKER_IN_API` | `true` |

`PORT` задавать не нужно: Render назначает его сам, приложение его
подхватывает.

4. **Create Web Service** и дождитесь `Live`.

Откройте выданный адрес — появится экран входа. Если вместо панели
видна страница с текстом README, значит развёрнут не тот сервис:
GitHub Pages показывает репозиторий, а не приложение. Нужен именно
веб-сервис на Render.

## Шаг 6. Владелец

Учётная запись создаётся один раз. В Render: **Shell** (вкладка сервиса):

```bash
npm run bootstrap:admin -w @nnm/backend
```

Команда напечатает временный пароль **один раз** — сохраните его сразу.
При первом входе система потребует его сменить.

Если вкладки Shell нет (на бесплатном плане её может не быть), задайте
переменные и перезапустите сервис:

```
BOOTSTRAP_ON_STARTUP=true
BOOTSTRAP_ADMIN_PASSWORD=<придуманный пароль>
```

После первого успешного входа **удалите обе переменные** — пароль не
должен оставаться в настройках хостинга.

Вход: `efimenkodaniil151@gmail.ru` и полученный пароль.

## Шаг 7. Источники

В панели: раздел **Источники → Добавить**. Публичные Telegram-каналы и
сообщества VK. Пока источников нет, лента пуста — это не поломка.

Сбор данных требует настройки доступа: см.
[SETUP-SOURCES.md](SETUP-SOURCES.md). Обход ограничений платформ,
закрытых сообществ и CAPTCHA не поддерживается и поддерживаться не
будет.

## Проверка установки

Команда проверяет конфигурацию, базу, схему, защиту данных, владельца и
источники, и по каждой проблеме говорит, что именно сделать:

```bash
npm run doctor
```

Пример вывода:

```
  ✓ База данных доступна
  ✓ Схема установлена: таблиц 21
  ✓ Защита данных: RLS на всех 21 таблицах
  ✗ Учётная запись владельца не создана — войти в панель невозможно
      → Выполните: npm run bootstrap:admin
```

## Что делать, если не работает

| Симптом | Причина и что сделать |
| --- | --- |
| Видна страница README, а не панель | Открыт GitHub Pages. Нужен адрес сервиса Render |
| `relation "users" already exists` | Схема ставилась не файлом `setup.sql`. Выполните `npm run migrate:baseline -w @nnm/backend` |
| `password authentication failed` | В `DATABASE_URL` не подставлен пароль вместо `[YOUR-PASSWORD]` |
| `no pg_hba.conf entry` / `SSL required` | Не задано `DATABASE_SSL=true` |
| Деплой падает на `COOKIE_SECURE` | В production требуется `COOKIE_SECURE=true` |
| Вход не сохраняется | Нет `TRUST_PROXY=true` либо `COOKIE_SECURE=true` без HTTPS |
| Лента пуста | Источники не добавлены или не настроен доступ к ним |
| Черновики слабые | Модель не подключена, работает разбор по правилам. См. [SETUP-AI.md](SETUP-AI.md) |

## Локальная установка

Если нужен запуск на своей машине (Node 20+ и PostgreSQL 16):

```bash
npm ci
cp .env.example .env          # впишите DATABASE_URL и два секрета
npm run migrate
npm run seed
npm run bootstrap:admin
npm run dev
```

Панель — на `http://localhost:5173`.
